# Upscaling

Upscaling is ComfyUI only: Metascan ships no upscaling model. User guide: `docs/upscaling.md`. A media item has at most one upscaled file (at its normal library path) and one original (in the Original folder, outside the library, read only for compare, re-upscale, revert and generation metadata).

- **Presets.** Kinds `upscale_image` (needs `MS_SOURCE_IMAGE`, `MS_SAVE`) and `upscale_video` (needs `MS_SOURCE_VIDEO`, `MS_SAVE`); the kind says the media type, so `video_target` / `video_mode` stay NULL. `MS_SOURCE_VIDEO` takes widget `video` or `file`, special-cased like `seed` / `noise_seed`. `MS_SEED`, `MS_POSITIVE`, `MS_NEGATIVE`, `MS_SCALE` (widget `value`), `MS_DENOISE` (widget `denoise`, or `value` on a primitive wired into the sampler: a node has one title and Ultimate SD Upscale is already `MS_SEED`; a linked input is no widget), `MS_MODEL` (widget `unet_name` or `ckpt_name`) and `MS_LORA_STACK` are optional, so `Bindings.positive` / `seed` / `seed_widget` are Optional for every kind and `GenerationParams.positive` / `seed` None mean "keep what the graph has"; `width` / `height` 0 likewise leave `MS_LATENT` / `MS_RESOLUTION` alone. A value the workflow cannot take raises `BindingError`. The `workflow_presets` kind CHECK rebuild in `_init_database` tests for the newest kind and carries `video_target` / `video_mode`: a new kind must extend both CHECKs and that test.
- **The dialog pre-fills what the image was made with** (`metascan/core/upscale_defaults.py`, `GET /api/upscale/state` → `generation {prompt, negative, seed, model, loras, blind}`): the media record's metadata (an upscaled item's record carries its original's), except the LoRAs of a T2I image, which come from its `t2i_images.loras` (`db.t2i_loras_for_path`: metadata parsing drops the file extension; otherwise `.safetensors` is added). A blind scorecard image gives no prompt or negative. The model and LoRAs are filled only when the workflow's baked `MS_MODEL` (`/config` → `model`) is in the same model folder as the image's (`same_family` / `sameModelFamily`, kept equal), else the dialog says so and offers to use them anyway. An `MS_LORA_STACK` node gets exactly the request's list (None or `[]`: empty), as for T2I. Every value the workflow cannot take is a 400 before anything is uploaded. Candidates record `denoise` (column added in place) for the tile label.
- **Detail (refine) prompts** (`metascan/core/upscale_refine_prompts.py`): built in, replaced by `data/upscale_refine_prompts.yml` when it holds a valid entry (`RefinePromptStore`, re-read on a changed mtime or size; a missing or unusable file gives the built-in ones, logged by exception type; `tests/test_upscale_refine_prompts.py` keeps the shipped file equal to `BUILT_IN`). `/config` carries `refine_prompts` and `refine_prompt_max_denoise` (0.3); `/state`'s `generation.refine_prompt` is `guess_refine_prompt` over `db.get_tags_for_file`: illustration from VLM / CLIP tags only (a prompt word names content as often as medium), else people from any tag, else scene. The dialog's Prompt menu (`promptSource`: `image`, `written` or a refine id) starts on `types/upscale.ts::defaultPromptSource` (a refine prompt at or below the limit on a workflow with `MS_DENOISE`, or when the image has no prompt; else the image's own) and follows a denoise or workflow change only while the text is unedited and not written from the image (`followDenoise`). Picking an entry sets prompt and negative; the "another model's prompt" warning applies to the image's own prompt only.
- **A prompt from the image** (`POST /api/upscale/prompt-from-image {source_path, model}`): for a workflow whose `MS_MODEL` folder names a T2I profile (`prompt_model_for`: `model_family` in `t2i_models.MODEL_PROFILES`; `/config` gives `prompt_model` / `prompt_model_label`, null without `MS_POSITIVE`), `T2iRunner.caption_image` has the prompt writer describe the image (`IMAGE_CAPTION_SYSTEM`, image attached; `plain_caption` strips parentheses, braces and `__` so the caption engine reads plain text), then `T2iRunner.generate_prompt` (seed 0, no directions, one variant, writer `base`) rewrites it like a typed caption. The original of an upscaled item is captioned. Errors map through `backend.api.t2i._http_error` (no writer 503, not an image 400, VLM failure 502). Nothing is stored and the caption is never logged. The dialog flags a missing prompt or one from another model family (`promptProblem`) and drops a reply after Reset or a workflow change (`writeSeq`).
- **The source is always the original.** `UpscaleRunner.start_run` reads `record.original_path` when a record exists, so upscaling again never stacks on a result.
- **Candidates are not media.** `generation_jobs.upscale_source_path` makes `ComfyClient.collect_outputs` skip `ingest_file`. Outputs go to `<data dir>/upscale_candidates/<uuid>/`, one folder per job, by `output_dir` + `output_name`, and the runner records them in `upscale_candidates` from the durable job row (seed, prompt and scale ride `params`). `ComfyClient.start()` runs before runners subscribe, so `recover_finished` sweeps done jobs with no candidate after they do. A run after an accept purges candidates older than `upscaled_at`; otherwise they stay until Discard. A run refuses (409) if the staging folder overlaps the library (`upscale_folders.staging_conflict`).
- **The swap is a journal; never reorder it** (`metascan/core/upscale_store.py`, its docstring is the reference). `prepared`: journal row first, then the copies (the original to `<Original>/<uuid><ext>` on a first upscale, the incoming file to `<target>.<token>.tmp`, which Import ignores). `placing` is written **before** anything in the library moves, then the library file is renamed aside (which doubles as the locked-file probe: `file_in_use` with nothing changed) and the `.tmp` replaces the target. From `placing` recovery rolls forward, because rolling back could delete the only original. `apply_upscale_swap` is one transaction: re-key through `_move_rows`, the `indices` `ext` / `path` keys, size / time / dimensions / format / timing in the columns and the `data` blob, pHash and embedding forgotten, the record, journal `committed`. Then `_tidy` removes the aside file (unlinked on a first upscale, since the original is safe; trashed otherwise), the candidate or the stored original, and the journal row; a file that will not go keeps the row for a retry.
- **Copies happen outside `scan.move_gate`, the critical section inside it** (`UpscaleService._critical`, polling the gate from its worker thread), with `hygiene_checks._unfinished` refusing while a scan or Full clean is unfinished (409 `library_busy`): the pending snapshot names paths a swap would move. `recover()` runs in the lifespan before anything watches the library (files and DB only: FAISS is not wired yet) and again from hygiene.
- **File facts are read from the source, never the `.tmp` copy** (`_complete_payload`): readers go by the extension, and a video named `.tmp` reads as an image. `_copy_verified` keeps size and time, so the row matches the placed file and `ChangedFiles` stays quiet.
- **The gate does not cover Import.** `_ingest_one` and `ChangedFiles._reingest` take no gate, so both, and `MissingFiles`, skip `db.upscale_busy_paths()` (open `placing` rows). Once committed the row is right and the normal rules apply. `save_media` is never used for a swap: ★, grade and playback speed stay.
- **Metadata comes from the original.** `Scanner._process_media_file` reads generation metadata and photo EXIF (not orientation, which describes the upscaled pixels) from `upscale_store.original_for`: a record for the path, `upscaled_size` matching (else another file landed there) and the original on disk. Dimensions, format and size are the upscaled file's, and a video's frame rate, duration and frame count are overlaid from its own probe. That one hook covers Full clean, `ChangedFiles` and every re-ingest. A failure there falls back to the file and never drops it.
- **The tables have no FK to media and `truncate_all_data` leaves them alone**, so a record outlives a Full clean. `upscale_records` is in `_lineage_paths`: a dangling record at a move's target would otherwise raise IntegrityError and roll back Import's whole batch. All three tables are on `NOT_TRANSFERRED_TABLES`; `upscale_records.file_path`, `upscale_candidates.source_path` and `generation_jobs.upscale_source_path` are on `MOVE_PATH_COLUMNS`.
- **Deletes.** `delete_keeping_signal` calls `release_upscale` for the files it trashed (the T2I / I2V deletes go through it too). `purge_keeping_signal` cannot: it does not know the purged paths. The hygiene check `UpscaleOrphans` covers those, under the gate and never during an unfinished Full clean: it finishes open swaps and releases records whose row and file are gone, leaving anything under a folder that cannot be seen.
- **The Original folder** (`upscale.original_root`, empty = `<data dir>/_original`, `upscale_folders.original_root`). `PUT /api/config` refuses a change that newly puts it inside a scan folder or generated-output root, or the reverse (400); a conflict already there is not that save's fault and does not block it. Changing it past existing originals is 409 there: `POST /api/upscale/original-folder` does it, through `OriginalsMoveProcess` (`originals_move`, `holds = ()`): copy, verify, repoint, delete, file by file, the setting last, the target in `originals_move.json`. Records hold absolute paths, so an interrupted move stays usable. Accept and revert are refused while a move is pending.
- **Background.** `UpscaleProcess(_GenerationProcess)`, id `upscale`: pause is the gate (`wait_unpaused` before the upload and each submit, `comfy.set_source_paused`), `is_writing` is true during an upload so a pause waits it out, and Stop calls `comfy.cancel_source` **before** the base `stop()` opens the gate. `_counts` falls back to `source_job_count`, since a job rehydrated after a restart has no in-memory run. `upscale_active()` is the `gpu_busy` reason. A run is in memory (like I2V): a restart loses what was not yet submitted.
- **Frontend.** `/stream` and `/thumbnails` answer `no-cache` with an ETag (`_revalidated`, `_not_modified`; Starlette's `FileResponse` never answers `If-None-Match`), since a swap puts new bytes behind the same URL. An element already on screen never asks again, so `bumpFileVersion` adds `?v=` on `media_swapped`, for the new path only: a bump on the old path sends tiles after a file that is gone. `LibraryView` handles `media_swapped` for every tab, and re-selects the item because `selectedMedia` is a copy. The dialog calls `CompareViewer.release()` before a swap: Windows refuses to rename a file a `<video>` holds, and the viewer remounts by `viewerKey`. The grid's `upscaled` is read beside the summary query, as a set of paths, never by a JOIN.
