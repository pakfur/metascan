# Text to image (T2I)

Moved out of the root CLAUDE.md so it loads only when you work with the files above;
the root CLAUDE.md still applies.

- **t2i flow (text→image).** A sparkles button at the top right of the main screen (left of Storyboards) opens `T2IDialog`. A caption — typed, or drawn at random from `data/t2i_captions/t2i_captions.csv` — goes through `resolve_caption` → a VLM rewrite in the selected model's style (`META_*` guideline) → a kind-`t2i` ComfyUI workflow. `metascan/core/t2i_runner.py::T2iRunner` mirrors `I2vRunner`'s layering: `ComfyClient` stays generic, jobs are correlated by `generation_jobs.t2i_batch_id`, ingest is keyed on it, and the `t2i` WS channel carries `batch_started` / `batch_step` / `batch_progress` / `batch_complete` / `batch_cancelled` / `batch_error` / `t2i_images_changed`. **Batches are server-side background tasks** — they survive closing the dialog, but their state is in memory, so a server restart drops unsubmitted steps (jobs already queued still ingest, with NULL `form_state`). Only one Random batch runs at a time (409 `random_batch_active`); Manual batches are unrestricted. Every image is its own job with latent `batch_size=1`: the dialog's *Batch Size* and *Count per Batch* are job counts, never the latent batch. User guide: `docs/t2i.md`.
- **The caption engine is a pure function of `(caption, seed, style, list snapshot)`** (`t2i_characters.resolve_caption`). **A character's draws are keyed on the caption text, never on the seed:** `sha256(f"{sha256(caption)}|{name}|{slot}|{salt}")` modulo the list length (`_caption_key`; **never `hash()`**; the text is hashed exactly as given, untrimmed, with `surrogatepass` so a lone surrogate cannot raise). One caption therefore always draws the same cast whatever the seed or identity style, and hair is forced distinct across the cast; any edit to the caption text, even a comma, re-rolls the whole cast (adding a character no longer leaves the others alone). The seed only picks plain wildcards (`sha256(f"{seed}|{token}|wildcard|0")`); never put it back in a character draw or the same scene changes people with every new seed. A first mention becomes the description: inline `with …` only when a verb follows, otherwise the head noun inline plus one trailing sentence — **never parentheses** (ComfyUI parses them as weights). Later mentions follow the model's identity style (`ref` "the copper-red-haired woman" / `noun` / `name`). `__HAIR__ __BREASTS__ __VAGINA__ __PENIS__` are owner-bound (a `his`/`her` pronoun, else the nearest character named before) and fall back to the bare word for body hair (`pubic __HAIR__`), fused suffixes (`__HAIR__brush`) or a missing list. A step's prompt seed is its FIRST image's seed (`t2i_images.prompt_seed`) and feeds only those wildcards. **A first mention names the age bracket** (`_Renderer.head_noun`): a drawn age >= `MIDDLE_AGED_FROM` (40) makes the head noun `middle aged <noun>`, >= `OLD_FROM` (71) `old <noun>` (70 is still middle aged), on the FIRST mention only — later handles, trailing sentences and `ResolvedCaption.characters` keep the plain noun and the raw drawn values. The age is the first number in the value (`t2i_ages.stated_age`, digits or spelled out); its number vocabulary is shared with the adult-only screen in `t2i_wildcards`, so keep it in that one module. Lists in `data/t2i_captions/` hot-reload; `age*.txt` rejects any number under 18, digits or spelled out (`twelve-year-old`); every list rejects minor-indicating words, phrases and word families (`teen*`, `child*`, `loli*`, `school girl`, …) and any `14-year-old` / `aged 12` style age under 18; the `nouns` and `names` of `characters.yml` go through the same screen (`_reject_reason`) — **adult-only is a load-time invariant, do not loosen it; add a test before you add a term.** `.gitignore` un-ignores `data/t2i_captions/` except `*.csv` (the CSV is user data).
- **Caption store.** `CaptionStore` indexes the CSV in memory on first use (line offsets + numpy columns; ~0.7 s and ~54 MB for 82,880 rows, ~11 ms per filter; caption text is read lazily by offset; records are quote-balanced physical lines so an embedded newline cannot break it). Do not load it into SQLite. `CaptionPicker` samples without replacement, then reshuffles. The CSV has no Size column — Random mode takes only the aspect ratio from the row.
- **Prompt generation reuses the existing model guidelines.** `t2i_prompt.compose_t2i_prompts` = `T2I_CAPTION_PREAMBLE` + the model's `META_*` entry (via `PromptStore`, hot-reloaded) + the existing `UNCENSORED_DIRECTIVE` / `SAFETY_DIRECTIVE` per `t2i.content_mode`; the user turn is `DESCRIPTION:\n<resolved>\n\nWrite the prompt now.` The shared `TargetModel` literal is deliberately NOT extended — `t2i_models.MODEL_PROFILES` (`krea2`, `qwen`, `sd`, `zimage`) map to YAML keys directly, and `META_KREA2` is a starter to tune. `Negative:` blocks are split with `meta_prompt_templates.split_negative_block`. No VLM (none recommended for the hardware, or its weights/projector/`llama-server` are not on disk — `vlm_select.vlm_model_installed`, wired in as `T2iRunner.vlm_installed`) → a deterministic fallback (the resolved caption; stock negatives for SDXL/Qwen) plus a warning; an `OSError` from spawning the VLM is turned into a `VlmError` (Manual: 502, batch: retry once, then fall back); a VLM error inside a batch retries once, then falls back so an unattended run never dies on one bad call.
- **GPU order and queue politeness.** In Random mode with `comfy.unload_vlm_during_generation` on, every prompt is written first, then the VLM is shut down (only when no Random batch is still prompting), then jobs are submitted; off → each step renders as soon as its prompt is ready. Jobs go through a per-batch window (`t2i.window`, default 4) that is released on terminal `job_update` events, so a large batch cannot starve i2v/storyboard jobs in `ComfyClient`'s shared FIFO. `T2iRunner._job_meta` is popped by the ingest task for `done` jobs (`job_outputs` fires BEFORE the terminal `job_update`, so popping on `done` would race the ingest) and on failed/cancelled events, with a bounded backstop.
- **`t2i_images` mirrors `i2v_videos`.** No foreign keys (list queries JOIN `media` and prune), as-rendered facts vs the editable `form_state`; `set_t2i_image_form_state` is the ONLY update and no route may write the fact columns. Seed policy, Batch Size and Count per Batch are session-local and never restored from `form_state`, so selecting a tile cannot trigger a large re-run.
- **T2I frontend.** The shared pieces in `components/generation/` and `composables/{useJobTracker,useFormAutosave}` are NEW files; I2V does not use them. The overlay closes only via ✕ (no `@click.self`). `useWebSocket` is called in the dialog (it needs setup context) and forwarded to `stores/t2i.ts::handleT2iEvent` / `handleComfyEvent`; the store never subscribes itself. **Autosave-drift rule:** the dialog form is written only by `initForm`, a tile load (`mergeFormState` then `autosave.markLoaded()`), the unlock patch (only when no image is selected) and the user — never add a watcher that writes it, or it will autosave into the selected image. **Starting a batch releases the selected image** (`autosave.flush()` then `store.clearSelection()` before the seed advances), and a Random batch takes the form over (tiles are refused, the boxes mirror `store.currentStep`), so an automatic change can never rewrite the saved form of the image it came from. The library grid reloads through ONE debounced, quiet `store.scheduleMediaReload` (`loadAllMedia({ silent: true })`, no dimming overlay) that both the dialog forwarder and `App.vue`'s always-on `t2i` bridge call, so images arriving while the dialog is closed still reach the grid. The viewer opens on a frozen snapshot of the images the grid shows because images arrive mid-batch; the filter panel is `position: fixed` (a panel absolutely positioned inside the scrolling form is clipped) and follows its button through the card's `@scroll.capture` (scroll events do not bubble, so one capture-phase listener sees every box that scrolls); Caption/Prompt are plain textareas because `TextEditPopup` collapses newlines; the scratch-form draft lives in localStorage under `metascan.t2i.draft.v1`. An unknown job id on the `comfy` channel is adopted by a one-off `GET /api/comfy/jobs/{id}` lookup (frames carry no batch id), so `t2i_batch_id` must stay on that route.
- **T2I dialog layout and the image grid.** Two panes: the form on the left, the images on the right. The form decides the card's height (up to 94vh); the image pane is `height: 0; min-height: 100%` so its tiles never make the row taller — don't let the grid's content size the dialog. The form column `.t2i-main` is ONE scroll box (`scrollbar-gutter: stable`) with a sticky `.t2i-top` (settings error, the editing bar) and a sticky `.t2i-run` footer (Batch Size, Count per Batch, Cancel, Generate, status), so every right edge shares one gutter — never give the fields a scroller of their own, or the pinned rows stop lining up with them. Below 900 px the panes stack and the card scrolls; nothing in it may shrink (`flex: none; min-height: auto`) or the footer and the images overlap the fields. The images are `components/generation/ThumbGrid.vue` (it replaced `ThumbStrip`; 3 wide, 132 px tiles, scrolls on its own, jobs slot first, full-width **Show more** last). **The grid renders `store.shownImages`, never `store.images`:** the store keeps every row it holds (`mergeImagePage` never drops a paged-in row) and `types/t2i.ts::imageWindow(held, shownPages, 60, hasMoreImages)` caps what is shown at whole pages, so a run pushes the oldest shown images behind Show more instead of growing the grid. `showMoreImages` fetches an older page (`loadOlder`, cursor = the last held id) only when the held rows cannot fill the next page, and still reveals held rows when that fetch fails; `open()` resets to one page.
- **Random Generate: the boxes decide batch 1, and the server decides what is on show.** The UI calls each caption step a "batch" (`Batch k/N` in the status line). A Random request may carry the Manual fields (`caption`, `prompt`, `negative`, `aspect_ratio`), and `t2i_runner` reads them as the FIRST batch: a non-blank `prompt` (`_supplies_first_step`) is a `_supplied_step` — no `CaptionPicker.next`, no VLM call, `aspect_ratio` validated like Manual's, `caption` stored as `None` when absent; no prompt but a non-blank `caption` (`_names_first_caption`) makes `_random_step` write a prompt for THAT caption (resolve + VLM, no draw, the ratio validated the same way); neither → a caption is drawn. Batches 2..N always draw a caption and write a prompt. A draw thrown away for batch 1 is a reroll the user never sees: `test_a_supplied_step_draws_no_caption` and `test_no_caption_is_drawn_for_step_one` spy on `CaptionPicker.next` because counting rows cannot see it (the picker never repeats the last row on a reshuffle). **The client keeps no hidden state about the Prompt box** (the old `readyPrompt` is gone): `t2iDialogForm.firstBatchSource(form)` is `'prompt'` when the box has text, `'caption'` when only the Caption box does, else `'draw'`, so the same boxes always do the same thing — including a prompt a finished run handed back (the next Generate renders it first) and one restored from the draft after a reload. The dice loads a caption and EMPTIES the Prompt and Negative (a rolled caption must never pair with the old prompt). Never reintroduce a flag that decides by where the text came from, and never write the Prompt from a watcher (the hand-back would rewrite it). **What the boxes show while a run goes is the server's call:** `batch_step` means "the batch on show" — the first one whose images are not all accounted for (`_Batch.rendering_step`; `_show_step` runs from `_announce_step` and `_settle`) — so prompts written ahead of the render (all of them with `unload_vlm_during_generation` on, the next one with it off) wait in `_Batch.steps` and never take the boxes; `_Batch.step` is what `GET /batches` lists and what the hand-back copies. Tests that need every step written read `BatchCase.written(batch_id)`, not the frames. **The seed box always holds the seed the next image will use:** `batch_progress.seed` and the listing's `seed` are `_Batch.current_seed` (the first image not yet accounted for, else `next_seed`) and move after every image; the dialog shows `store.liveSeed` while locked and ALSO sets `form.seed = next_seed` when Generate is pressed (Random as well as Manual), so a closed dialog, a reload and the unlock all find it right. Randomize plans a fresh random `next_seed` (null only when increment/decrement ran out of range). The store nulls `currentStep` when a Random batch begins, so the locked boxes would blank until the first `batch_step` frame arrives: while the request names its first batch (`supplyingFirstStep`, set before the POST because the WebSocket frames can beat the response; a prompt or a caption) the boxes keep the form's values, matching on `step === null` and never on `??` so a later batch's null negative cannot fall back to stale form text.
- **Workflows and the smart-folder rule.** The dialog lists every kind-`t2i` preset (no schema change). `workflow_validation._KIND_VALIDATORS` runs kind-level checks regardless of target/mode (`t2i`: warns on a missing `MS_LORA_STACK` / `MS_NEGATIVE`). `PresetRegistrationDialog` takes a `kind` prop; `t2i` presets carry no video tag. The "Generated with T2I" rule (`field: 't2i'`, bool) reads `GET /api/t2i/paths` through a `makePathSetCache` helper, refetched on `t2i_images_changed`, after an image delete, and on a forced `loadTagPaths`.
- **Caption directions** (`metascan/core/t2i_directions.py`, spec `docs/superpowers/specs/2026-10-02-t2i-caption-directions-design.md`). Classification columns are appended to the CSV by `scripts/caption_classifier/merge.py` (never edits caption text; `--replace` keeps `<stem>.bak-<time>.csv`, which must stay git-ignored — it is a full copy of user data and `.gitignore` also covers the older `*.csv.bak-*` names). `CaptionRow.classification` is None unless the row's `Caption SHA1` matches its text, so an edited caption never borrows a stale classification. `CaptionStore.find(caption)` is exact-text (SHA-1-prefix map built in the normal scan; the text is compared on a hit). Snippet lists live in `data/t2i_captions/directions/` — a subdirectory so the top-level wildcard loader never reads them — and every line goes through `_reject_reason` (adult-only screen, no parentheses). Snippet choice is `sha256(f"{seed}|direction|{key}|0")` (`_draw`). Parts are act → kissing → emotion; emotion fires on `1 − Emotion Explicit ≥ emotion_missing_min` (implicit counts as missing); `.pov` lists are preferred when `Partner` is not `none`; `sfw` drops act and kissing and the sensual emotion list. No direction ⇒ system and user prompts are byte-identical to before (`DIRECTION:` block only when non-blank; the fallback appends the text). Nothing is stored per image; the dialog checkbox is localStorage-only (`metascan.t2i.directions.v1`). A failing `find` is a step warning, never a failed batch.
