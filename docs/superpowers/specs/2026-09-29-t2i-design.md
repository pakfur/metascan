# Text-to-Image (t2i) — Design

**Date:** 2026-09-29
**Status:** Draft — awaiting review

## 1. Overview

A "Text to Image" dialog, opened from an icon button at the top right of the
main screen, next to Storyboards. The user supplies a caption — typed by hand,
or drawn at random from `data/t2i_captions/t2i_captions.csv` (82,880 rows)
under column filters — and the pipeline:

1. **Resolves** the caption: character-name tokens (`__ALICE__` …) and
   body-part tokens (`__HAIR__` …) become seeded, deterministic character
   descriptions (§3).
2. **Rewrites** it, with the local VLM, into a prompt in the selected model's
   style (Krea2, Qwen, SDXL, ZImage) using that model's existing guideline in
   `data/meta_prompt.yml` (§5).
3. **Renders** it through a registered kind-`t2i` ComfyUI workflow, in batches
   (*Batch Size* × *Count per Batch*) owned by a server-side runner that keeps
   going when the dialog is closed (§6).

Results ingest as ordinary visible library media, appear in a strip at the
bottom of the dialog, and each keeps the dialog contents that produced it. A
T2I tab in the config dialog sets the output folder, name prefix and
workflows, and a smart-folder rule finds T2I images.

The stack parallels i2v (`I2vRunner`, `i2v_videos`, `I2VDialog`) but shares
only `ComfyClient`, pure helpers and the prompt store. **I2V is not modified.**
Dialog layout: `docs/t2i_screenshot.txt`.

### Decisions locked during brainstorming

- **Entry point:** an icon button (`pi-sparkles`, tooltip "Text to Image") at
  the top right of the main screen, immediately left of Storyboards. Desktop
  only. *(The user's recommendation.)*
- **Batches run on the server** and keep running if the dialog is closed or
  the page is reloaded; reopening the dialog reattaches.
- **GPU order follows `comfy.unload_vlm_during_generation`** (existing
  setting, no new one): on → write every prompt first, unload the VLM, then
  render; off → render each step as soon as its prompt is ready.
- **Character lists:** we define the format and ship starter lists for the
  general characteristics (adult-only). The user supplies the body-part lists
  (`breasts.txt`, `vagina.txt`, `penis.txt`); a missing list makes its token
  fall back to the plain word.
- **Later mentions of a character** use a *descriptive handle* ("the
  copper-red-haired woman") for Krea2, Qwen and ZImage, and the plain noun
  for SDXL. Configurable per model.
- **Approach:** a parallel stack plus a few *new* shared frontend pieces;
  I2V is left untouched (it has an uncommitted edit in flight and no
  frontend test coverage). I2V may adopt the shared pieces later.
- **The CSV has no Size column.** In Random mode only the aspect ratio comes
  from the row; Size stays whatever the dialog says.
- **"Batch Size" and "Count per Batch" are job counts.** Every image is its
  own ComfyUI job (each needs its own seed) with latent batch size 1.
- **Evaluation rule:** prompt-related tests use hand-written known captions
  and model outputs. They never use library prompts or rows from the real
  CSV.

## 3. Caption engine

Pure function of `(caption, seed, identity_style, list_snapshot)`. Same
inputs, same output — always.

### 3.1 Tokens

- Token grammar: `_{2,}([A-Z][A-Z0-9]*)_{2,}` — two or more underscores each
  side, so the malformed `____BREASTS____` (4 rows in the CSV) parses.
- **Character names** (from `characters.yml`): female `ALICE BELLA CLARA
  DIANNA EMMA`, male `ADAM BOB`. EMMA and BOB never occur in today's CSV but
  are supported.
- **Characteristic tokens** — `HAIR BREASTS VAGINA PENIS`, i.e. the slots in
  `token_slots`. They stand in for the word itself (`her __HAIR__`, `pubic
  __HAIR__`, `__HAIR__brush`, `__VAGINA__l opening`).
- Any *other* `__TOKEN__` with a `token.txt` list resolves as a plain seeded
  wildcard (same value everywhere in the caption). Without a list it becomes
  its lowercase word.
- A caption with no tokens passes through unchanged.

### 3.2 Cast and draws

- The cast is the character names present, in canonical list order.
- Each characteristic (`age ethnicity skin eyes face hair body`, in that
  order) is drawn per character as
  `int.from_bytes(sha256(f"{seed}|{name}|{slot}|{salt}")[:8], "big") % len(list)`.
  `sha256`, not `hash()`, so results are stable across processes and Python
  versions. Consequences: adding BELLA to a caption does not change ALICE;
  editing a list changes results (documented).
- `hair` is forced distinct across the cast by incrementing `salt` until the
  value is unused (canonical order, so stable). If the list is too short, the
  colliding characters' handles fall back to the plain noun.
- Gendered lists: `<slot>.female.txt` / `<slot>.male.txt` override
  `<slot>.txt` for that gender when present.
- Lists: one value per line, blanks and `#` comments ignored, duplicates
  dropped case-insensitively, file order preserved.

### 3.3 First mention

The first token for a character becomes its description, capitalised when it
starts a sentence. Head: `<article> <age> <ethnicity> <noun>` (article `an`
before a vowel or a number spoken with a vowel: 8x, 11, 18). Details: the word
`with` followed by the drawn skin, eyes, face, hair and body values joined as
`a, b and c`.

- **Slots the caption already spells out via a token are omitted** from the
  details (a caption that says `__HAIR__` does not also get hair in the
  intro).
- **Inline** (`head` + `with …`) only when the next word is not a preposition,
  conjunction, possessive or punctuation (`with and or in on at who whose
  wearing holding while as 's , . ; :`) and the name is not part of a
  compound subject (`X and Y`, `X, Y`). Any non-alphanumeric character
  after the token counts as punctuation (so `! ? " ) - …` defer the details
  too); `'s`, the curly apostrophe and U+02BC are possessive; the end of
  the string stays inline.
- Otherwise **head only** goes inline and the details move to **one trailing
  sentence** appended to the caption: `The <handle> has skin, eyes … .`
  A caption without a final full stop gets one (a dangling `,;:` becomes it)
  before the trailing sentence. Parentheses are never used — ComfyUI
  parses them as weighting syntax.

### 3.4 Later mentions (identity styles)

| Style | Later mention | Notes |
|---|---|---|
| `ref` (default: krea2, qwen, zimage) | `the copper-red-haired woman` | Derived from a hair value ending in ` hair`: words hyphen-joined plus `-haired`. Possessive-safe. Falls back to `noun` if the value does not end in ` hair`. |
| `noun` (default: sd) | `the woman` | Ambiguous once two characters share a gender. |
| `name` | `Alice` | First mention becomes `… woman named Alice`. Supported, not a default (possessive first mentions read clumsily); its trailing sentence uses the name (`Alice has …`). |

Overridable per model via `t2i.identity` in config.

### 3.5 Characteristic tokens

- **Owner.** For `breasts`/`vagina` the owner is the current female
  character, for `penis` the current male; for `hair` the pronoun decides —
  the last six words of the sentence before the token are scanned
  backwards and the NEAREST `his/him/he` (male) or `her/she/hers` (female)
  decides. Otherwise the owner is the nearest
  character named before the token, else the first cast member of the right
  gender, else (a typed caption with no cast) a default owner (ALICE, or ADAM
  for `penis`) who gets no intro.
- **Bare-word fallback** (the token becomes its lowercase word) when: the
  token is followed directly by a letter (`__HAIR__brush` → `hairbrush`,
  `__VAGINA__l` → `vaginal`); for `hair`, the previous word is in
  `body_hair_prefixes` (`pubic body facial chest arm leg underarm armpit
  stomach`); the list is missing or empty; or there is no owner of the right
  gender (this also adds a warning). A token that falls back to the bare word
  does not count as "spelled out", so its character keeps that slot in the
  intro.

Known limit: owner detection is a heuristic. In multi-character captions the
worst case swaps which person gets which colour; the scene is never broken and
each owner stays self-consistent.

### 3.6 Files (`data/t2i_captions/`)

`characters.yml` (defaults built in, so a missing file is not an error):

```yaml
names:  {female: [ALICE, BELLA, CLARA, DIANNA, EMMA], male: [ADAM, BOB]}
nouns:  {female: woman, male: man}
slots:  [age, ethnicity, skin, eyes, face, hair, body]      # draw set and order
intro:  {head: [age, ethnicity], with: [skin, eyes, face, hair, body]}
token_slots:  [hair, breasts, vagina, penis]
token_gender: {breasts: female, vagina: female, penis: male}
body_hair_prefixes: [pubic, body, facial, chest, arm, leg, underarm, armpit, stomach]
```

Lists hot-reload (mtime check of ~12 files per resolve call — no watcher).
Hair values should end in ` hair` (`auburn hair`, `jet-black hair`).

### 3.7 Guards

- **Adult only.** In an `age` list (`age.txt`, `age.female.txt`,
  `age.male.txt`) any line with an integer under 18, or a spelled-out age from
  thirteen to seventeen, is rejected. In *every* list, a line containing a
  minor-indicating term (`teen`, `teenage`, `teenager`, `underage`, `minor`,
  `child`, `kid`, `preteen`, `juvenile`, `schoolgirl`, `schoolboy`, `loli`,
  `shota`, `under 18`, `under eighteen`; plurals such as `teens`, `kids` and
  `children` count) is rejected, and so is any line containing a parenthesis —
  parentheses never belong in a generated prompt. Rejections are logged at
  WARNING and surfaced as
  `wildcards.warnings` in `GET /api/t2i/config`. A slot with no valid lines is
  omitted from descriptions. Starter lists use ages 21 and up.
- Resolution never raises on data problems; it degrades to the bare word or an
  omitted slot and reports a warning.

### 3.8 Interface

`resolve_caption(caption, seed, style, library) -> ResolvedCaption(text,
characters: {NAME: {slot: value}}, warnings: [str])`.

## 4. Caption store and filters

`CaptionStore(csv_path)` builds its index on first use and rebuilds when
`(mtime_ns, size)` changes. Measured on the real file: **0.7 s build, ~54 MB
RSS, ~11 ms for a four-predicate filter, ~7 µs per lazy caption read.** No
database, no sidecar cache.

- **Index:** record byte offsets (int64), and per-row aspect-ratio and nudity
  codes, `artistic_quality` / `erotic_score` / `pornographic_score`
  (float32), `males` / `females` (uint8), and clothing item sets. Caption
  text is read on demand by offset.
- **Records** are quote-balanced physical lines, so an embedded newline in a
  caption cannot break the index. Clothing is a Python-literal list string,
  parsed with `ast.literal_eval` and treated as empty on failure.
- **Required columns:** `Caption`, `Aspect Ratio`. Others enable their filter;
  a missing optional column drops that filter from `meta()`. A missing or
  unreadable file reports `csv.error` in `GET /api/t2i/config` and Random
  mode is disabled; so does an empty or header-only file or a CSV syntax
  error (the store is never partially available). Rows with a blank caption
  are not indexed.
- **`CaptionFilter`** (all keys optional; unknown keys are a 400):

```json
{ "nudity": ["none","partial","full"],
  "artistic_quality":   {"min": 0.0, "max": 1.0},
  "erotic_score":       {"min": 0.0, "max": 1.0},
  "pornographic_score": {"min": 0.0, "max": 1.0},
  "males": {"min": 0, "max": 3}, "females": {"min": 0, "max": 5},
  "aspect_ratios": ["3:2"], "clothing_any": ["corset"], "clothing_none": ["tie"] }
```

- **Picking:** uniform among matches, without replacement within a run; if a
  run needs more captions than match, the pool is reshuffled and reused.
- **Surface:** `meta()` (columns, option lists, numeric ranges, `total`),
  `count(filter)`, `get(row_id)` and `picker(filter, rng)`, which returns a
  `CaptionPicker` whose `next()` implements the picking rule above
  (`CaptionFilterError` on a bad filter or zero matches). An empty list in a
  filter means no constraint.

## 5. Prompt generation

`POST /api/t2i/prompt {caption, seed, model}` — review-only, writes nothing.

1. `resolve_caption(caption, seed, profile.identity, library)`.
2. `compose_t2i_prompts(profile, resolved, content_mode) -> (system, user)`:
   - system = `T2I_CAPTION_PREAMBLE` + the model's guideline (`profile.meta_key`
     from the prompt store) + the existing `UNCENSORED_DIRECTIVE` /
     `SAFETY_DIRECTIVE` per `t2i.content_mode` (`uncensored` default; `sfw`;
     `default` = none);
   - user = `DESCRIPTION:\n<resolved caption>\n\nWrite the prompt now.`
3. Reuse of the VLM lifecycle exactly as `I2vRunner.generate_prompt`:
   `get_vlm_client()` → `pick_vlm_model()` → `ensure_started()` →
   `generate_text(system_prompt, user_prompt, temperature=0.6,
   max_tokens=profile.max_tokens, timeout=240)`.
4. `split_negative_block(raw)` (factored out of
   `meta_prompt_templates.parse_output`, which then calls it) splits a
   `Negative:` block for models with `has_negative`. The runner parses a
   reply with `t2i_prompt.parse_t2i_output(profile, raw)`, which also strips
   parentheses; `fallback_prompt` strips them too.
5. Response `{prompt, negative, resolved_caption, warnings}`.

**Failure handling.** No VLM installed or recommended (`VlmSelectError` /
no client) → **200 with the fallback prompt** and a warning. A VLM/timeout
error → **502** (Manual: the user retries; inside a batch: retry once, then
fall back with a warning so an unattended run never dies on one bad call).
Fallback prompt = the resolved caption; models with a negative also get a
stock negative, and SDXL a stock quality prefix (YAML keys below).

### 5.1 Model profiles (`t2i_models.py`)

| id | label | guideline key | negative | identity | dim multiple | max tokens |
|---|---|---|---|---|---|---|
| `krea2` | Krea 2 | `META_KREA2` (new) | no | `ref` | 16 | 420 |
| `qwen` | Qwen-Image | `META_QWEN` | yes | `ref` | 16 | 320 |
| `sd` | SDXL | `META_SDXL` | yes | `noun` | 64 | 480 |
| `zimage` | Z-Image | `META_ZIMAGE` | no | `ref` | 16 | 280 |

The shared `TargetModel` literal (storyboard and Prompt Playground) is **not**
extended; profiles reach the YAML through the prompt store directly. The
`max tokens` values are starting points, tunable in `t2i_models.py`.

### 5.2 New keys in `data/meta_prompt.yml` (hot-reloaded)

- `META_KREA2` — starter derived from the Flux.1 prose rules plus public
  Krea 2 guidance: natural-language prose, specific rather than generic,
  camera / composition / lighting / texture, longer detailed prompts do
  better; no negative (the Turbo checkpoint ignores it). **A starting point
  for the user to tune.**
- `T2I_CAPTION_PREAMBLE` — states that no image is attached, that the
  DESCRIPTION is ground truth (read "the image" in the guideline as the
  description), that every stated trait, garment, pose, setting and camera cue
  must be kept (physical-trait phrases verbatim), that no people, objects or
  identities may be added or changed, and that the output format is exactly
  what the guideline specifies.
- `T2I_FALLBACK_PREFIX_SD`, `T2I_FALLBACK_NEGATIVE_SD`,
  `T2I_FALLBACK_NEGATIVE_QWEN`.

### 5.3 Negative prompt in the UI

A small Negative box under Prompt appears only when the selected model has
one (Qwen, SDXL). It is sent only if the workflow binds `MS_NEGATIVE`;
otherwise the batch response carries a one-time warning that it is ignored.

## 6. Batch runner

### 6.1 Start

`POST /api/t2i/batches` takes the whole form (§8). Every static problem fails
synchronously with a named 400 before anything is queued:

- unknown model; workflow missing, or not kind `t2i` (`PresetNotFoundError`);
  `BindingError` (bindings do not resolve; LoRAs supplied but no
  `MS_LORA_STACK`);
- `count_per_batch > 1` with a Fixed seed; Manual with `batch_size != 1`;
  counts above the configured limits;
- Manual with an empty prompt or an unsupported aspect ratio; Random whose
  filter matches nothing;
- a configured `output_root` that is not a directory (never auto-created);
- seed outside `0..2^31-1`, non-positive megapixels.

**409** `random_batch_active` if a Random batch is already running (one at a
time; Manual batches are unrestricted). Success returns `{batch_id,
total_images, warnings}`, and a background task then owns the run.

### 6.2 Steps and seeds

- **Manual:** one step — the given caption (provenance only), prompt,
  negative and aspect ratio.
- **Random:** per batch, pick an unused caption, take its aspect ratio, write
  the prompt (§5, with the in-batch retry/fallback), allocate the step's
  seeds.
- **Seeds** advance per policy across the whole run: Fixed keeps the seed,
  Increment/Decrement step by one, Randomize draws from a non-deterministic
  RNG. Increment/Decrement stop the run early — with a message — rather than
  leave `0..2^31-1` or repeat a seed; the run's total is reduced to what was
  actually planned and a warning says why. With Fixed, every step uses the
  same seed and therefore draws the same cast. The step's **character seed**
  is its first image's seed (stored as `prompt_seed`), so a prompt is
  reproducible from the seed shown in the dialog. The next unused seed is
  PLANNED at start and reported (from `GET /batches` and every
  `batch_progress`) so the dialog can show it at once: increment adds the
  planned image count, decrement subtracts it, Fixed keeps the seed, and
  it is `null` under Randomize or when the range ran out (no unused seed
  remains). Under Randomize the first image uses the request's seed and
  the rest are drawn at random.
- Size × aspect ratio → `t2i_dims(aspect, megapixels, profile.dim_multiple)`:
  both edges on the multiple, aspect error weighted 4:1 against pixel-budget
  error (the `i2v_dims` search idea with a lower aspect weight, independent
  code: at i2v's 10:1 the 64-grid drifts up to 47% off the budget), floor of
  one multiple. Ratios beyond 32:1 and budgets outside (0, 1000] MP are
  rejected (`T2iFormError`).

### 6.3 GPU order

- `comfy.unload_vlm_during_generation` **on** (default): the prompt phase
  writes every step's prompt first; then, if the VLM is running and no
  Random batch is still prompting, the runner calls `vlm.shutdown()`; then
  the render phase submits every job. The first image appears only after the
  last prompt is written. A Manual Generate also unloads before submitting, so
  the next Generate Prompt pays a VLM reload.
- **off:** each step renders as soon as its prompt is ready, overlapping the
  next step's prompt.

### 6.4 Rendering

Each image is one job (`batch_size=1`) via `ComfyClient.submit(...,
t2i_batch_id=…, output_dir=…, output_name=…)`. Jobs go through a **window**
(`t2i.window`, default 4 unfinished jobs per batch), released on each of the
batch's terminal `job_update` events, so a 200-image batch cannot bury I2V and
storyboard jobs in ComfyClient's shared FIFO queue.

- `GenerationParams(positive=prompt, seed, width, height, batch_size=1,
  negative=…, loras=…)`; the negative is dropped (with a warning) when
  `bindings.negative` is unset; LoRAs without `MS_LORA_STACK` were already a
  400.
- **Placement:** `resolve_output_target(root, prefix, now, number)` from
  `i2v_output.py`, with `t2i.output_root` / `t2i.output_prefix`; an empty root
  means `<comfy.output_root>/t2i` (created on demand); files always go
  through `output_name` and `_unclobbered`. A per-process, strictly
  increasing number (epoch seconds) is appended, as in `I2vRunner`.
- **Per-job form snapshot** (`_job_meta[job_id]`): batch id, model, caption,
  `prompt_seed`, aspect ratio, megapixels, loras, negative and the editable
  `form_state`. The **ingest task pops it** (it owns the entry for a `done`
  job — `job_outputs` fires before the terminal `job_update`, so popping on
  `done` would race the ingest); failed and cancelled jobs pop on their
  terminal `job_update`; a bounded backstop (oldest entries evicted beyond
  2,000) covers anything else. I2V's map never pops for failed jobs.

### 6.5 Ingest and accounting

`handle_job_event` (registered with `comfy_client.on_job_event`) reacts to
`job_outputs` for jobs whose row has `t2i_batch_id`: it creates one
`t2i_images` row per file (as-rendered facts from the job's stored `params`
and `_job_meta`; `render_s` from the job timestamps — `finished_at` may still
be NULL at this moment), then emits `t2i_images_changed`. Media is never
hidden (`collect_outputs` already ran `Scanner.ingest_file`). Counters:
`images_done` on ingest, `images_failed` on a failed job, `cancelled` on a
cancelled one; when they sum to the total the batch emits `batch_complete`.

### 6.6 Cancel, reattach, restart, shutdown

- **Cancel:** `POST /api/t2i/batches/{id}/cancel` marks the batch cancelled,
  cancels the run task (including an in-flight VLM call), cancels every
  unfinished job through `comfy.cancel(job_id)` (`gather`, exceptions
  collected), and emits `batch_cancelled`. Unsubmitted steps simply never
  exist. The dialog's Cancel cancels every active t2i batch.
- **Submit failure:** an exception from `comfy.submit` mid-run stops the run:
  the batch cancels its own unfinished jobs, releases the window, emits
  `batch_error` once and leaves the active list. Jobs that already finished
  stay ingested.
- **Reattach:** `GET /api/t2i/batches` returns active batches with their
  counters and current step snapshot; the dialog also rebuilds job tiles from
  `GET /api/comfy/jobs?state=…` filtered on `t2i_batch_id`.
- **Restart:** batch state is in memory. A server restart drops unsubmitted
  steps; jobs already queued are re-enqueued by `ComfyClient` and still
  ingest — without `_job_meta` they get NULL `form_state` (I2V precedent).
- **Shutdown order** in the lifespan: `comfy_client.shutdown()`, then
  `storyboard_runner.aclose()`, `i2v_runner.aclose()`, `t2i_runner.aclose()`
  (cancels batch tasks, drains ingest tasks).

## 7. Data model

### 7.1 `t2i_images`

Mirrors `i2v_videos`: no foreign keys; list queries JOIN `media` and lazily
prune rows whose media is gone.

```
id INTEGER PRIMARY KEY AUTOINCREMENT,
file_path TEXT NOT NULL UNIQUE,      -- POSIX; returned native
batch_id TEXT,
-- as-rendered facts (never edited; they agree with the embedded metadata):
model TEXT, preset_id INTEGER, caption TEXT, prompt_used TEXT, negative_used TEXT,
seed INTEGER, prompt_seed INTEGER, width INTEGER, height INTEGER,
megapixels REAL, aspect_ratio TEXT, loras TEXT /*json*/, render_s REAL,
comfy_prompt_id TEXT,
created_at TEXT NOT NULL DEFAULT (datetime('now')),
-- the editable copy:
form_state TEXT /*json*/
```

Methods (sync, under the DB lock): `create_t2i_image(**facts) -> int`,
`get_t2i_image(id)`, `set_t2i_image_form_state(id, form_state) -> bool` (**the
only update; never add a route that writes the fact columns**),
`list_t2i_images(limit, before_id)` (newest first; merges `is_favorite`,
dimensions, `file_name`), `list_t2i_paths()` (native paths, JOIN `media`),
`delete_t2i_image(id) -> (bool, purged_paths)` (also deletes the media row —
indices and `folder_items` cascade; the caller trashes the files through
`metascan/utils/trash.py`).

### 7.2 `generation_jobs.t2i_batch_id`

Nullable TEXT (uuid4 hex), added with `_idempotent_add_column`, no
`REFERENCES` (the `panel_id` / `i2v_source_path` precedent). Threaded through
`create_generation_job` and `ComfyClient.submit` (whose DB arguments are
passed positionally — check the call site). `GET /api/comfy/jobs` must
return it, and `GenerationJob` in the frontend types gains it.

### 7.3 `form_state` (the editable copy)

Fields: `mode`, `filter`, `caption`, `model`, `preset_id`, `megapixels`,
`aspect_ratio`, `seed`, `prompt`, `negative`, `loras`. Seeded at ingest from
the dialog exactly as submitted; loaded when a tile is selected; autosaved via
`PATCH /api/t2i/images/{id}` (validated by `t2i_form.validate_form_patch`).
`form_state_for_row` fills gaps from the facts (stored values win
field-by-field). **Seed policy, Batch Size and Count per Batch are
session-local** (actions, not properties of an image), so selecting a tile
can never trigger a large re-run.

## 8. API

Errors follow I2V: 400 validation, 404 unknown id, 502 ComfyUI/VLM failure,
503 no runner. All routes are `async def` except `output-preview`.

| Route | Body / params | Response |
|---|---|---|
| `GET /api/t2i/config` | — | `get_t2i_config` (flat keys, incl. `window`, `max_batch_size`, `max_count_per_batch`) + `models` (id, label, has_negative, identity), `aspect_ratios`, `seed_policies`, `seed_max`, `csv` (`available`, `total`, `error?`), `wildcards` (`slots`, `warnings`) |
| `GET /api/t2i/captions/meta` | — | filter columns, option lists, ranges, `total` |
| `POST /api/t2i/captions/count` | `{filter}` | `{count, total}` |
| `POST /api/t2i/captions/random` | `{filter}` | `{id, caption, aspect_ratio, …}`; 404 if no match |
| `POST /api/t2i/captions/resolve` | `{caption, seed, model}` | `{resolved_caption, characters, warnings}` |
| `POST /api/t2i/prompt` | `{caption, seed, model}` | `{prompt, negative, resolved_caption, warnings}` |
| `POST /api/t2i/batches` | see below | `{batch_id, total_images, warnings}` |
| `GET /api/t2i/batches` | — | active batches: id, mode, state, counters, current step |
| `POST /api/t2i/batches/{id}/cancel` | — | `{status: "cancelled"}` (idempotent) |
| `GET /api/t2i/images` | `limit=60`, `before_id?` | array, newest first |
| `PATCH /api/t2i/images/{id}` | form-state patch | the full updated row with a complete `form_state` |
| `DELETE /api/t2i/images/{id}` | — | `{status: "deleted"}` (never 204) |
| `GET /api/t2i/paths` | — | `List[str]` native paths (smart folder) |
| `GET /api/t2i/output-preview` | `root`, `prefix` | `{path, error, warnings}`, always 200; sync `def`; a blank `root` previews `<comfy.output_root>/t2i` |

`POST /batches` body:

```json
{ "mode": "manual|random", "model": "krea2", "preset_id": 1,
  "megapixels": 1.0, "seed": 321424,
  "seed_policy": "fixed|increment|decrement|random",
  "batch_size": 1, "count_per_batch": 1,
  "loras": [{"name": "x.safetensors", "strength": 0.8}],
  "caption": "…", "prompt": "…", "negative": "…", "aspect_ratio": "3:2",
  "filter": { } }
```

`caption`/`prompt`/`negative`/`aspect_ratio` are Manual fields; `filter` is a
Random field. `loras` is a typed model (`name`, `strength`) — I2V's untyped
list 500s on a missing key.

Workflows use the existing `/api/comfy/presets` routes; LoRAs use
`/api/comfy/loras`; star = `PATCH /api/media`; job listing and cancel are the
generic `/api/comfy/jobs` routes. `POST /api/comfy/submit` is untouched.

## 9. WebSocket — new `t2i` channel

`{channel: "t2i", event, data}` via `ws_manager.broadcast_sync`:

| Event | Data |
|---|---|
| `batch_started` | `{batch_id, mode, total_steps, total_images}` |
| `batch_step` | `{batch_id, step, total_steps, caption, aspect_ratio, seed, prompt, negative, warnings}` — fills the Caption / Prompt / Aspect / Seed boxes |
| `batch_progress` | `{batch_id, phase: "prompting\|rendering", images_done, images_failed, images_total, next_seed, last_error?}` |

## 12. Frontend

### 12.1 Entry and shell

`ContentSearchBar.vue`: new `t2i` emit and a `pi-sparkles` Button immediately
left of Storyboards. `LibraryView.vue`: a `t2iOpen` ref and `<T2IDialog
v-if>`; desktop only (the bar lives in the desktop tree). The overlay closes
only through its ✕ (I2V's deliberate rule).

### 12.2 `T2IDialog` (top to bottom, per `docs/t2i_screenshot.txt`)

1. **Caption** textarea. A collapsible read-only *Resolved caption*.
2. **Generate Prompt** · **Manual / Random Caption** radio (🎲 loads one
   caption to preview) · **Filter** popover.
3. **Model · Workflow · Size (MP) · Aspect Ratio · Seed** (`SeedControls`:
   seed input, 🎲, policy Fixed / Increment / Decrement / Randomize).
4. **LoRAs** (`LoraListEditor`, unchanged).
5. **Prompt** textarea; collapsible **Negative** (§5.3).
6. **Generate / Cancel**, **Batch Size**, **Count per Batch**, and a status
   line ("Batch 12/40 · image 3/4 · writing prompts / rendering").
7. **Strip.**

Behaviour:

- **Filter popover:** Nudity (none/partial/full), the three scores (min–max),
  Males / Females (min–max), Aspect Ratio, Clothing (has any / has none),
  with a live "N captions match" (debounced `POST /captions/count`).
- **Random mode:** while a Random batch runs, Caption / Prompt / Aspect / Seed
  are read-only live views of the current step (`batch_step`) and Generate is
  disabled. On completion they unlock: Caption, Prompt and Aspect hold the
  last step's values and Seed shows the next unused seed (`next_seed`).
- **Manual mode:** Batch Size locked at 1. Count per Batch above 1 needs a
  non-Fixed policy: Fixed forces an *effective* count of 1 (the field keeps
  what was typed, and the dialog sends the effective count; the server's 400
  for Fixed with a count above 1 only guards direct API use). After a batch
  queues, the seed box shows the next unused seed. Aspect is user-chosen from
  the 11 CSV ratios.
- **Duplicate-submit `confirm()`** guard (I2V's `requestSignature`), Manual
  only.
- **Draft:** with no tile selected the scratch form is restored from
  `localStorage` on open (per-viewer convenience; every access try/catch).
- Caption and Prompt are **plain textareas** — `TextEditPopup` collapses
  newlines on save.

### 12.3 Strip

Job tiles (progress %, ✕ cancels / dismisses a failed one) then image tiles,
newest first: click selects, double-click opens the viewer, ★ toggles
`is_favorite`, ✕ deletes (confirm; trashes the file). Label = `seed · W×H`;
tooltip = model + start of the prompt. 60 per page with "older" at the end.

- **Viewer:** `MediaViewer` (`allowDestructive=false`) on a **frozen snapshot**
  of the strip taken when it opens — images arrive mid-batch and would shift
  its index.
- **Persistence:** selecting a tile loads its `form_state` (§7.3); edits
  autosave after 600 ms, serialised (`useFormAutosave`, capturing the image id
  at flush time); **Stop editing** returns to the scratch form. Flush on tile
  switch, Stop editing, close and unmount. Starting a batch (Manual or Random)
  flushes and then releases the selected image BEFORE the seed advances, so
  the automatic advance can never rewrite the saved form of the image it came
  from (the user asked that the dialog contents that generated an image
  persist); the form keeps its values as scratch state. Tiles cannot be
  selected while a Random batch runs.
- Don't show "No images yet" until the first list load has completed and no
  batch is active (the job tile can vanish before the refetch lands).

### 12.4 Shared pieces (new files; I2V untouched)

`SeedControls` (seed / 🎲 / policy), `JobTile`, `ThumbStrip` + `ThumbTile`
(`select(item, evt)` keeps the `detail > 1` guard, `open`, `favorite`,
`delete`, `#jobs` slot), `useJobTracker({match})`, `useFormAutosave`.

### 12.5 Store and WebSocket

`stores/t2i.ts`: config, caption meta, images, active batches, job chips,
selection. The dialog subscribes to `t2i` and `comfy` (needs component setup
context) and forwards to store handlers. Handle config-load failures with a
toast (I2V's `open()` leaks a rejection). The library refresh on
`t2i_images_changed` is **debounced (~1.5 s)** and shared: the store exposes
`scheduleMediaReload` (a debounced `loadAllMedia({ silent: true })`, which
skips the dimming "Loading media…" overlay), and `App.vue`'s always-on `t2i`
bridge calls it (and refreshes the smart-folder path set), so images that
arrive while the dialog is closed still reach the grid.

### 12.6 Config tab (`ConfigT2ITab`, new `t2i` `TabKey`)

Output folder (`DirectoryPicker`), name prefix with the debounced live
preview (`GET /output-preview`), workflows (list of `t2i` presets,
"Register workflow…", per-model default-workflow selects), size list and
default, content mode. Save follows the spread-merge PUT.

### 12.7 Smart-folder rule

`RuleField` `'t2i'`, label "Generated with T2I", bool. Output paths from
`GET /api/t2i/paths`, cached like the I2V set (via a small
`makePathSetCache(fetch, isReferenced)` helper used by the new rule; I2V's
copy is not migrated), fetched only while a saved folder or the open editor
uses the rule, refetched on `t2i_images_changed`, after an image delete, and
on forced `loadTagPaths`. Not a column on `/api/media`, so the covering
indexes do not change. `SmartFolderEditor` gets the sibling of its
`field === 'i2v'` line. No `migrateSmartFolder` change.

- Mobile.
- Resuming batches after a server restart.
- Per-model LoRA lists (ComfyUI's list is global; `LoraListEditor` caches it).
- Editing captions or the CSV in-app.
- cfg / sampler / checkpoint overrides (no `MS_*` titles exist).
- Reference-image (`ref`) or image-to-image workflows.
- Moving I2V onto the shared components.

- Opening the dialog from a media item or pre-filling it from one.

## 16. Risks and known limits

- **`META_KREA2` is a starter.** It needs the user's tuning in the YAML.
- **VLM unload is not coordinated with the storyboard runner.** A storyboard
  synthesis running at the same moment could lose its VLM; both re-`ensure_started`,
  so the worst case is one retried call.
- **Owner detection for characteristic tokens is a heuristic** (§3.5).
- **Editing a list changes results** for the same caption and seed (index
  arithmetic); reordering a file does too.
- **The shared ComfyClient queue is FIFO across features.** The window keeps a
  big batch from monopolising it, but a queued t2i job still waits behind
  earlier storyboard / i2v jobs.
- **`ComfyClient` re-reads the preset's workflow at dispatch time**, so editing
  a preset mid-batch affects the remaining jobs.
- **An untracked mock, `docs/t2i_screenshot.txt`, and an uncommitted edit to
  `metascan/core/i2v_compiler.py`** exist in the working tree; neither is
  touched by this spec.

## 17. Suggested phasing (for the implementation plan)

One plan, five phases, each independently testable:

1. **Caption engine, wildcards, caption store** (§3–4, pure and I/O modules,
   starter lists, `characters.yml`) — no server needed.
2. **Prompt generation** (§5): profiles, YAML keys, composition, fallbacks,
   `split_negative_block`, the guideline-adherence probe.
3. **Backend service** (§6–11): DB table and column, `ComfyClient` kwarg,
   `t2i_form`, runner, API, WebSocket, config, kind-level validator,
   lifespan wiring — exercised end to end through `TestClient` with fakes.
4. **Dialog** (§12.1–12.5): shared pieces, store, `T2IDialog`, entry icon.
5. **Config tab, preset-dialog `kind` prop, smart-folder rule, docs**
   (§12.6–12.7, §14).
